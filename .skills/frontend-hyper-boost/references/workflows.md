# Workflows

## New frontend

1. Confirm audience, conversion, content, surfaces, privacy, and deploy target.
2. If AI Forge / hub / agents / hyper-boost: open `premium-21st-registry.md` and
   map product zones → ref IDs **before** layout (REQUIRED premium bar).
3. Create information architecture and calm semantic shell.
4. Choose experience profile and one primary visual direction (+ counterpoint).
5. Map no more than three hero interactions and all input equivalents.
6. Implement core responsive layout with premium depth (not flat admin chrome).
7. Add progressively enhanced motion/render layers (orbs, particles, shaders,
   galleries) matching the registry grammar.
8. Represent live AI jobs (audit/process/phase) and inter-agent flows visually.
9. Run verification matrix and static audit.
10. Record changelog, **ref mapping**, evidence, risks, and next action.

## Existing frontend audit

1. Inspect source, build, runtime, screenshots, analytics, and deploy state.
2. Compare coded behavior with declared product objectives.
3. Report at most five problems ordered by severity.
4. Separate visual taste from usability, accessibility, security, and truth.
5. Propose the smallest high-leverage patch set.
6. Implement only within granted scope.
7. Verify the complete user story, not isolated components.

## Component intake

1. Prefer IDs from `premium-21st-registry.md` when the surface is AI Forge.
2. Open the live example and observe default, hover, focus, active, touch, and
   scroll behavior.
3. Read the source/license only when adoption is intended.
4. Re-specify the pattern in local tokens and semantic structure
   (`design-tokens.md`).
5. Add reduced-motion and low-power fallback before shipping.
6. Record provenance, registry ID, and modifications.

## Handoff packet

- outcome and audience;
- route/component map;
- **premium ref map** (`#n 21st.dev → UI zone`);
- design tokens;
- interaction map (include live agent-state + handoff-flow language);
- responsive/accessibility matrix;
- package and license notes;
- build/test commands;
- deploy target and environment requirements;
- known risks and next physical action;
- explicit statement that delivery meets PREMIUM bar (or list gaps).
