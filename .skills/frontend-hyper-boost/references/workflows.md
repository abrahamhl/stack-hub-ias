# Workflows

## New frontend

1. Confirm audience, conversion, content, surfaces, privacy, and deploy target.
2. Create information architecture and calm semantic shell.
3. Choose experience profile and one primary visual direction.
4. Map no more than three hero interactions and all input equivalents.
5. Implement core responsive layout.
6. Add progressively enhanced motion/render layers.
7. Run verification matrix and static audit.
8. Record changelog, evidence, risks, and next action.

## Existing frontend audit

1. Inspect source, build, runtime, screenshots, analytics, and deploy state.
2. Compare coded behavior with declared product objectives.
3. Report at most five problems ordered by severity.
4. Separate visual taste from usability, accessibility, security, and truth.
5. Propose the smallest high-leverage patch set.
6. Implement only within granted scope.
7. Verify the complete user story, not isolated components.

## Component intake

1. Open the live example and observe default, hover, focus, active, touch, and
   scroll behavior.
2. Read the source/license only when adoption is intended.
3. Re-specify the pattern in local tokens and semantic structure.
4. Add reduced-motion and low-power fallback before shipping.
5. Record provenance and modifications.

## Handoff packet

- outcome and audience;
- route/component map;
- design tokens;
- interaction map;
- responsive/accessibility matrix;
- package and license notes;
- build/test commands;
- deploy target and environment requirements;
- known risks and next physical action.
