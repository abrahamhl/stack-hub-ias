# Evidence Fabric: Case Study

## Problem: AI Coding Context Fragmentation
When multiple AI agents (Codex, Claude, Jules, Grok) collaborate on a repository, context is often lost when a session ends. Valuable engineering reasoning, test failures, and architectural decisions are fragmented across temporary chats, distinct agent log files, and unstructured git commits. This makes agent handoffs difficult and creates gaps in technical provenance.

## Solution: Provider-Neutral Evidence Fabric
We built a deterministic "Session Evidence Fabric" that converts any agent's work into durable, auditable artifacts. It defines a canonical `Session Capsule v1` schema that normalizes facts, inferences, and claims made by agents, backing them with hard evidence like git commits and line ranges.

## Interesting Engineering
- **Provenance**: Distinct separation between what an agent claims and what is verified by the system.
- **Claim Verification**: Claims must reference explicit evidence (e.g., git commits) to be considered VERIFIED.
- **Conflict Resolution**: The fabric detects when two agents make contradictory claims (e.g., conflicting architecture decisions) and flags them for review using git timestamps.
- **Staleness**: If a file or line range tied to a claim is modified by a later commit, the claim is automatically marked as STALE.
- **Redaction**: A robust Regex-based engine identifies and redacts secrets (API keys, passwords, tokens) before any public export, emitting only safe metadata.
- **Deterministic Export**: Generates both a `PUBLIC_ENGINEERING_CASE.md` (for recruiters/portfolios) and a compact `HANDOFF_PACKAGE.md` (for seamless continuation by another agent).

## Human Value
The primary value of this system is seamless continuation. Another agent can pick up a project and immediately know "Where am I?", "What changed?", and "What failed?", without relying on hidden or proprietary chat context. This creates a transparent, resilient AI development pipeline.

## Public/Private Boundary Confirmation
The Evidence Fabric strictly preserves the boundary between public and private data. It does **not** expose raw agent sessions, private prompts, local source trees, personal user data, or secrets. All public exports are strictly derived from sanitized claims and manually vetted metadata generated by the `Redactor` engine.
